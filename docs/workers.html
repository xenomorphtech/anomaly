🪖 CODEX WORKERS — UNITS THAT DO WORK

commander — RTS context HQ · docs/workers.html · updated 2026-09-02

A unit garrisoned at a base is now a real worker: an OpenAI Codex CLI session (codex exec --json) running inside the base's repository. The commander dispatches a pylon (task) to a unit; the unit works the task, its command/file/message traffic lands on the base's comms wall, and its closing status line moves the pylon to done or blocked. Follow-up orders resume the unit's codex thread, so it keeps its context between turns.

Nothing about the wasm programs changed — modules are pure logic that reads/reduces building state; workers are processes that change the world outside the HQ (your repos). Both report into the same event log.

1 · Base setup: the repo

Units work in the base's cwd. A base without one can't dispatch (the room shows an amber warning). Set it via the control API — it persists in space.jsonl:

curl "127.0.0.1:7700/base?i=0&cwd=/home/you/albion"
curl "127.0.0.1:7700/base?i=0&sandbox=danger"          # optional, see below
curl "127.0.0.1:7700/base?i=0&model=gpt-5.6-sol"       # optional override
fieldmeaningdefault
cwdworking root passed to codex (-C); must existnone → no workers
sandboxread-only · workspace-write · danger-full-access (alias danger/yolo → --dangerously-bypass-approvals-and-sandbox)workspace-write
modelcodex -m override~/.codex/config.toml

Pass an empty value (&model=) to clear a field. Approvals are always never in headless mode: anything the sandbox forbids simply fails and the unit has to work around it or report BLOCKED.

workspace-write cannot commit. Codex mounts .git read-only inside that sandbox, so a unit told to commit will answer BLOCKED: grant write access to .git… (observed on the first real run). Either commit yourself once the pylon is done, or set sandbox=danger for bases whose repo you trust the unit with.

2 · Dispatch

Enter a pylon's room (2×click the crystal) and hit ⚙ DISPATCH WORKER or press w. Or from the API:

curl "127.0.0.1:7700/pylon?i=0&title=fix+the+gate+desync"
curl "127.0.0.1:7700/dispatch?i=0&title=fix+the+gate+desync"            # → {"ok":true,"agent":"cx-1"}
curl "127.0.0.1:7700/dispatch?i=0&title=...&agent=cx-2&prompt=start+from+packets/"

Unit choice: the named agent, else the first idle unit, else a new one is hired (cx-N). Dispatch always opens a fresh codex thread. The pylon goes doing, the unit goes working (spinning gear in the garrison).

The standing orders

Every dispatched unit gets the same wrapper around its assignment (worker::prompt): unit id, base name and goal, the pylon title, your optional notes, and one rule — end with exactly one status line:

DONE: <one-line summary>      → pylon done, unit idle
BLOCKED: <what you need>      → pylon blocked, unit blocked (⚠ on the map)
PARTIAL: <what remains>       → pylon stays doing, unit idle — tell it to continue

No status line at all is treated like PARTIAL.

3 · Follow-up orders, halting, firing

curl "127.0.0.1:7700/tell?i=0&agent=cx-1&s=also+add+a+regression+test"   # resumes the thread
curl "127.0.0.1:7700/halt?i=0&agent=cx-1"                                     # kill the running turn
curl "127.0.0.1:7700/fire?i=0&agent=cx-1"                                     # remove the unit

/tell runs codex exec resume <thread_id> in the base's repo, so the unit answers with everything it already learned. A blocked unit that receives an order goes back to working and its pylon back to doing. The room shows ■ HALT cx-1 while a turn runs and ⚙ RE-DISPATCH cx-1 afterwards (fresh thread, same pylon).

One turn per unit at a time. A unit that was mid-turn when commander quit comes back idle on restart (the process is gone); its thread id survives, so /tell can pick the work back up.

5 · State

curl -s 127.0.0.1:7700/state | jq '.workers_running, .projects[0].cwd, .projects[0].agents'
[
  {
    "id": "cx-1", "state": "idle", "task": "fix add() in calc.py …",
    "blocked_on": null, "running": false,
    "thread_id": "019a…", "turns": 1, "tokens": 14210,
    "last_report": "11:05", "last_msg": "…\nDONE: add() now sums; test_calc.py passes"

tokens is codex's reported input+output per turn summed, cached input included — it tracks context size more than spend; the topbar meter is the real budget. Persisted per unit in space.jsonl: thread_id, last_msg, turns, tokens; per base: cwd, sandbox, model.

6 · Under the hood

src/worker.rs — Host spawns codex exec --json --color never --skip-git-repo-check -C <cwd> -s <sandbox> [-m model] [resume <id>] - with the prompt on stdin. A reader thread parses the JSONL (thread.started, item.completed, turn.completed, turn.failed, error) into worker::Out and sends it over a channel; CommanderApp::worker_pump drains it every frame next to wasm_pump. Stderr is tailed for the exit report. COMMANDER_CODEX overrides the binary (default codex on PATH).

The subscription meter in the topbar (src/codex.rs) reads the same ~/.codex/sessions rollouts these workers write, so unit spend shows up in the weekly gauge within a minute.
